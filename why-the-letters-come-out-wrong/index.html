The gap between what you ask a hosted image model for and what it hands back.

Why the letters come out wrong

A poster comes back looking right until you read it. The headline is nearly a word. The small print is a convincing texture of letters that spells nothing. Everyone has seen this; fewer people have a model of why it happens, and the model is worth having because it tells you which fixes will work.

The model is drawing letters, not setting type

A typesetting system has glyphs. It looks up a character, finds its outline in a font, and places it. The letter a is the same shape every time because it is the same object every time.

An image model has no glyph table. It has learned what text looks like in photographs and designs — the statistics of strokes, spacing, contrast against a background, the way a sign is lit. When it renders a word it is producing something that has the visual properties of that word in that context. Sometimes those properties resolve into the correct characters. Sometimes they resolve into shapes that are locally letter-like and globally wrong.

This is why the failure mode is so specific: text is almost always typographically plausible and semantically broken. It is not random noise. It is a very good drawing of the idea of a word.

Three consequences that follow directly

Short text works far better than long text. Every additional character is another chance for the sequence to drift. A three-word headline is a different difficulty class from a paragraph, and no amount of prompt engineering moves a paragraph into the easy class.

Large text works far better than small text. Small lettering occupies fewer pixels, so there is less signal available to make the characters distinct. The illegible small print at the bottom of a generated poster is not the model being lazy; there was no room to be correct in.

Re-editing an image with text in it degrades the text. This is the one people trip over. If your tool applies edit two to the output of edit one, the model re-reads the rendered lettering as image content and re-renders it. It does not know those pixels were meant to be a specific string, so it reproduces something similar. Four edits later the headline has drifted into a different word, and each individual step looked fine.

What actually helps

Ask for less text, larger. The single highest-leverage change. Move body copy out of the generation entirely.

Name the text as an invariant when editing. If you are changing something else, say explicitly that the lettering must not change. It does not guarantee preservation, but the alternative — saying nothing — guarantees the model treats it as fair game.

Prefer a tool that recomputes from your original. If each edit is derived from the source file plus the accumulated instruction list rather than from the previous render, the text is re-rendered from the same starting point every time instead of from a copy of a copy. Drift stops compounding. It does not stop drift, but it stops the multiplication.

Composite rather than generate. For anything that must be exactly right — a brand name, a price, a legal line — generate the image without it and lay the type on afterwards in whatever tool you already use. Five minutes, and the result is correct rather than probably correct.

Proof at 100%. Generated text often reads correctly in a thumbnail and falls apart at full size, because at thumbnail scale you are reading your own expectation.

The test that tells you which tool you have

Generate an image with a short headline. Make four unrelated edits in sequence — change a colour, move an object, adjust the light, alter the background. Then compare the headline in pass four against pass one.

If it has drifted, your tool is chaining. That is worth knowing before you plan a revision-heavy job with text in frame, because no instruction you write on pass four can undo what happened on passes one through three.

The chaining half of this is a property of the tool rather than the model, which is why it is worth checking: an editor that recomputes from the original instead of re-editing its own output keeps the fourth pass derived from your upload.
